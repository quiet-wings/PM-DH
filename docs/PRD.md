## 1. 개요

**마음버블**은 걱정을 비눗방울에 적어 터뜨리는 스트레스 해소 웹서비스다. 서비스를 알리기 위해 **마음버블 블로그**를 열고, **블로그 글만 근거로 답하는 AI 챗봇**을 붙인다. 독자는 내 상황에 맞는 답·출처 글·바로 해 볼 기능을 받고, 운영자는 반복 응대를 자동화하며 **답하지 못한 질문을 다음 글 주제로 쓴다.**

## 2. 문제

**문제 정의(한 문장)**: 지친 독자는 답이 어느 글에 있는지 몰라 이탈하고, 1인 운영자는 같은 질문에 반복해서 답한다.

> **독자**: 지친 20~30대는 긴 글을 읽을 여유가 없다. ① 답이 **어느 글에 있는지 몰라** ② 이탈하고, 호흡·게임 같은 마음버블 기능으로 이어지지 않는다(블로그 → 서비스 **유입 경로 없음**).
> **운영자**: 1인 운영이라 ④ **같은 질문에 반복해서 답하고**, ⑤ 독자가 **무엇을 궁금해하는지 데이터가 없어** 글 주제를 감으로 정한다. ③ 위기 표현은 놓치면 안 된다.

| 데스크리서치 | 현황 | 시사점 |
|---|---|---|
| 블로그 검색(티스토리 등) | 키워드 일치 검색이라 "잠이 안 와요" 같은 문장 질문에 약함 | 문장형 질문을 이해하는 검색 필요 |
| 범용 AI 챗봇 | 내 글·내 서비스를 모르고 출처가 없음 | 답의 근거를 내 글로 묶어야(RAG) 신뢰·유입이 생김 |
| 멘탈케어 앱 | 기능은 많지만 가입·설치 장벽 | 가입 없는 웹이라 "블로그 → 바로 체험"이 쉬움 |

**타깃 사용자**
- **지친 독자(주)**: 20~30대 직장인·학생, 퇴근길·잠들기 전 모바일 접속.
- **정신건강의학과 환자(주, 상용화 단계)**: 의료진이 권하는 **보조 도구**로 진료 사이 자기관리를 돕는다. 선행 조건: 치료 대체 금지, 인허가 검토, 건강정보 동의·암호화, 임상 근거. MVP는 진단·처방성 답변 금지, 개인 기록 미수집.
- **운영자(부)**: 응대 시간을 줄이고 글 주제를 데이터로 정하고 싶은 1인 기획자.

| 순위 | 기능 | 설명 | 문제 |

| P0 | 남용 방지 | 300자 제한, 브라우저당 분당 10회, 중계 서버 분당 30·일 600회·허용 주소만, 키는 서버 비밀값에만 | 운영 |
| P1 | 기능 추천·갭 로그·데모 모드 | 글 주제에 맞는 기능 링크 / 답 못 한 질문을 개인정보 가려 Firestore에 기록 / AI 장애 시 문단 요약으로 대체 | ②⑤ |
| P2 | 관리자 글쓰기 자동화 | 초안 → 제목·요약·태그·SNS 문구 (**이번 구현 범위 제외**, 차기) | ④ |

**범위 밖**: 로그인, 대화 기록 저장, 진단·상담 대체.

## 5. 출시·운영·마케팅과 리스크

- **출시**: push → Actions(테스트·빌드) → Firebase Hosting. AI는 Cloudflare 중계가 Claude API 호출(키는 서버 비밀값에만, D-017).
- **운영**: 주 1회 Firestore `content_gaps` 질문으로 글 주제 선정. 새 글은 push만 하면 챗봇이 바로 근거로 씀.
- **마케팅(마음버블 유입)**: 글마다 "마음버블에서 해 보기" 버튼과 답변의 기능 링크로 서비스에 연결, 위로카드 공유로 블로그에 되돌아오게 한다. 지표는 기능 링크 클릭률(UTM).
- **기관 서비스로의 활용**: 근거 문서로만 답하기·위기 규칙 우선·개인 기록 미수집은 병원·기관용 보조 도구의 필수 조건이다. 갭 로그·안전 테스트 방식을 기관 콘텐츠 검증 절차로 확장한다(D-008).

| 리스크 | 대응 |
|---|---|
| AI 환각·위기 사용자 | 근거 문단만 쓰도록 지시, 근거 없음·위기·의료 질문은 AI 없이 규칙으로 처리 |
| 호출 한도 초과·장애 | 서버 일일 상한, 실패·15초 초과 시 데모 답변 |
| 개인정보 | 질문 원문 미저장, 갭 로그 마스킹, 처리방침 공개 |
| 병원 연계 규제 | 웰니스 보조로 먼저 출시, 병원과 공동 검증 후 인허가 결정 |
