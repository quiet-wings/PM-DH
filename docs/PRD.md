## 1. 개요

**마음버블**은 걱정을 비눗방울에 적어 터뜨리는 스트레스 해소 웹서비스다. 서비스를 알리기 위해 **마음버블 블로그**를 열고, **블로그 글만 근거로 답하는 AI 챗봇**을 붙인다. 독자는 내 상황에 맞는 답·출처 글·바로 해 볼 기능을 받고, 운영자는 반복 응대를 자동화하며 **답하지 못한 질문을 다음 글 주제로 쓴다.**

## 2. 문제

> **독자**: 지친 20~30대는 긴 글을 읽을 여유가 없다. 답이 **어느 글에 있는지 몰라** 이탈하고, 호흡·게임 같은 행동으로 이어지지 않는다.
> **운영자**: 1인 운영이라 **같은 질문에 반복해서 답하고**, 독자가 **무엇을 궁금해하는지 데이터가 없어** 글 주제를 감으로 정한다. 블로그에서 서비스로 가는 **유입 경로도 없다.**

| 데스크리서치 | 현황 | 시사점 |
|---|---|---|
| 블로그 검색(티스토리 등) | 키워드 일치 검색이라 "잠이 안 와요" 같은 문장 질문에 약함 | 문장형 질문을 이해하는 검색 필요 |
| 범용 AI 챗봇 | 내 글·내 서비스를 모르고 출처가 없음 | 답의 근거를 내 글로 묶어야(RAG) 신뢰·유입이 생김 |
| 멘탈케어 앱 | 기능은 많지만 가입·설치 장벽 | 가입 없는 웹이라 "블로그 → 바로 체험"이 쉬움 |

**타깃 사용자**
- **지친 독자(주)**: 20~30대 직장인·학생, 퇴근길·잠들기 전 모바일 접속.
- **정신건강의학과 환자(주, 상용화 단계)**: 병원 치료 프로그램에서 의료진이 권하는 **보조 도구**로 진료 사이 자기관리를 돕는다. 선행 조건: 치료 대체 금지, 디지털의료제품법상 해당 여부 검토·인허가, 건강정보 별도 동의·암호화, 임상 근거. MVP는 진단·처방성 답변 금지, 개인 기록 미수집으로 설계한다.
- **운영자(부)**: 응대 시간을 줄이고 글 주제를 데이터로 정하고 싶은 1인 기획자.

## 3. 목표와 성공 지표 (출시 후 4주)

| 북극성 지표 | 품질 | 안전 | 정직성 | 마케팅 | 운영 |
|---|---|---|---|---|---|
| 출처 붙은 답변 수 주 50건 | 근거 있는 질문의 출처 포함률 90%↑ | 위기 표현 안전 안내 100% | 범위 밖 질문 "아직 없는 내용" 100% | 답변 → 기능 링크 클릭률 15%↑ | 갭 질문 → 새 글 월 2편 |

출시 전 검증: 단위테스트 59/59 통과(위기 감지·범위 밖 정직성·출처 포함 각 100%).

## 4. 솔루션과 기능 요구사항

**흐름**: 질문 → 입력 검증 → 위기·의료 질문 검사 → 블로그 문단 검색 → Gemini가 검색된 문단만으로 답변 → 답변 + 출처 글 + 마음버블 기능 링크

| 순위 | 기능 | 설명 |
|---|---|---|
| P0 | 블로그 | 마크다운 글 → 정적 페이지, 마음버블 톤 디자인, 모바일 우선 |
| P0 | 근거 기반 답변 | 검색 상위 4개 문단만 근거로 3~5문장, 출처 글 링크 |
| P0 | 모르면 모른다고 | 근거가 없으면 AI를 부르지 않고 "아직 블로그에 없는 내용" |
| P0 | 위기·의료 대응 | 위기 표현은 AI 없이 109·1577-0199·119 안내, 진단·약 질문은 의료진 상담 권유 |
| P0 | 남용 방지 | 300자 제한, 브라우저당 분당 10회, App Check, 키를 코드에 넣지 않음 |
| P1 | 기능 추천·갭 로그·데모 모드 | 글 주제에 맞는 기능 링크 / 답 못 한 질문을 개인정보 가려 Firestore에 기록 / AI 장애 시 문단 요약으로 대체 |
| P2 | 관리자 글쓰기 자동화 | 초안 → 제목·요약·태그·SNS 문구 (차기) |

**범위 밖**: 로그인, 대화 기록 저장, 진단·상담 대체, 마음버블 앱 본체 수정.

## 5. 출시·운영·마케팅과 리스크

- **출시**: GitHub push → Actions(테스트·빌드) → Firebase Hosting. AI는 Firebase AI Logic(Gemini, 무료 Spark 요금제).
- **운영**: 주 1회 Firestore `content_gaps` 질문으로 글 주제 선정. 새 글은 push만 하면 챗봇이 바로 근거로 씀.
- **마케팅**: 글마다 "마음버블에서 해 보기" 버튼, 답변의 기능 링크, 위로카드 공유에 블로그 주소.

| 리스크 | 대응 |
|---|---|
| AI 환각 | 근거 문단만 쓰도록 지시, 근거 없으면 AI 호출 생략 |
| 위기 사용자에게 부적절한 답 | 규칙으로 먼저 처리, AI에 맡기지 않음 |
| 무료 한도 초과·장애 | 호출 제한, 실패·15초 초과 시 데모 답변 |
| 개인정보 | 질문 원문 미저장, 갭 로그는 전화번호·이메일 마스킹 |
| 병원 연계 규제 | 웰니스 보조로 먼저 출시, 병원과 공동 검증 후 인허가 결정 |

## 6. 추후 개선 방향 — 더 단순하고 깔끔하게

지금 마음버블은 첫 화면에 버튼과 장식이 많다. 다음 버전은 **"적고 → 터뜨리고 → 위로받기"만 한눈에 보이는 화면**으로 덜어낸다: 통계·필터는 접고, 소리·테마·언어는 설정 하나로 묶고, 배경 버블·폭죽은 줄인다. 잘 안 쓰이는 기능은 사용률을 보고 숨기거나 뺀다.
