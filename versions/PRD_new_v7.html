2. 개요

스트레스 해소 웹서비스 마음버블의 블로그에 **블로그 글만 근거로 답하는 AI 챗봇 「클로버」**를 붙여, 독자는 답·출처·기능을 바로 받고 운영자는 반복 응대를 줄이며 답 못 한 질문을 글 주제로 쓴다.

3. 문제

3.1 데스크리서치 (3C) — 고객: 20~30대, 퇴근길·잠들기 전 모바일로 짧게 읽음 → 긴 글 대신 바로 답. 경쟁: 블로그 검색은 문장 질문에 약하고, 범용 AI는 내 글을 몰라 출처가 없고, 멘탈케어 앱은 가입 장벽 → 내 글 근거 문장형 Q&A, 가입 없는 웹. 자사: 마음버블 기능(호흡·게임·글귀·서점)과 글은 있으나 블로그→서비스 연결·질문 데이터가 없고 운영 1인 → 유입 경로·질문 데이터 확보가 핵심.

3.2 문제 목록

# 문제 타깃 해결 방향
① 답이 어느 글에 있는지 몰라 찾다 지친다 독자 문장 질문 → 근거 글로 답
② 읽다 이탈하고 마음버블 기능으로 이어지지 않는다 독자 답변·글에 기능 링크
③ 같은 질문에 반복해서 답한다 운영자 챗봇이 글로 대신 답
④ 독자가 무엇을 궁금해하는지 데이터가 없다 운영자 답 못 한 질문 기록

3.3 문제 검증 — 확인: 조사가 붙은 문장 질문은 키워드 검색으로 못 찾았고(①, 성공·실패 #4), 블로그→마음버블 링크는 끊겨 있었다(②, D-012). 미확인: 실제 이탈률·반복 문의 수 → 출시 후 4주 질문·갭·UTM 집계 + 지인 10명 3문항 설문.

3.4 문제 최종 정의 — 우선순위(MoSCoW, 개발 기간 2일·1인): Must ①③(챗봇 하나로 함께 해결) · Should ②④ · Won't(이번) 관리자 글쓰기 자동화, 글 3줄 요약(D-001). 전제 조건: 위기 표현은 놓치지 않는다.

지친 독자는 답이 어느 글에 있는지 몰라 이탈하고, 1인 운영자는 같은 질문에 반복해서 답한다.

4. 해결 방안

4.1 솔루션 정의: 블로그 글만 근거로 답하고 출처와 마음버블 기능을 함께 주며, 모르면 모른다고 하고 위기에는 사람의 도움을 먼저 안내하는 챗봇.

4.2 AS-IS / TO-BE

AS-IS TO-BE
컨셉·기능 글 목록·키워드 검색을 직접 뒤짐 문장으로 물으면 근거 글로 답 + 출처 + 기능 링크
타겟 막연한 방문자 지친 20~30대(1순위)·운영자 / 확장: 병원 보조 도구(D-008)
비즈니스 모델 블로그→서비스 경로 없음 블로그 = 무료 유입 채널, 추후 서점 제휴·기관 도구

4.3 예상 성과 (OKR, 4주) — O 지친 독자가 블로그에서 답을 찾고 마음버블로 이어진다 · KR1 출처 붙은 답변 주 50건 · KR2 기능 링크 클릭률 15%↑ · KR3 갭 질문으로 새 글 월 2편

5. 가설 및 지표

가설 지표 목표
근거 글로 바로 답하면 답을 찾고 반복 응대가 준다 (①③) 출처 포함률 / 출처 붙은 답변 90%↑ / 주 50건
답과 함께 기능을 권하면 서비스로 이동한다 (②) 기능 링크 클릭률(UTM) 15%↑
모르면 모른다고 하면 신뢰·데이터가 쌓인다 (④·전제) 정직 응답·위기 안내율 / 갭 글 100% / 월 2편

페르소나: 퇴근길 29세 직장인, 잠들기 전 "잠이 안 와요"를 찾지만 긴 글은 못 읽는다. 핵심 카피: "긴 글 말고, 클로버에게 물어보세요 🍀"(다정한 존댓말, 진단·처방 표현 금지)

6. 기능적 요구사항

순위 기능 설명 문제
P0 근거 기반 답변 상위 4문단만 근거로 3~5문장, 근거 번호 = 출처 번호 ①③
P0 모르면 모른다고·위기 대응 근거 없으면 "아직 없는 내용"+갭 기록, 위기·의료는 AI 없이 109·의료진 안내 ④·전제
P1 기능 추천·데모 모드 글 주제별 마음버블 기능 링크, AI 장애 시 문단 요약 ②
P2 관리자 글쓰기 자동화 초안 → 제목·요약·태그 (이번 제외) ③

유즈케이스: "잠이 안 와요" → 검증 → 위기·의료 검사 → 문단 검색 → Claude가 근거로 답 → 출처 [1] + "호흡 쉼터 열기". 범위 밖: 로그인, 대화 저장, 진단 대체.
