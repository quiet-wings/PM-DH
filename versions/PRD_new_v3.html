1. 개요

마음버블은 걱정을 비눗방울에 적어 터뜨리는 스트레스 해소 웹서비스다. 서비스를 알리기 위해 마음버블 블로그를 열고, 블로그 글만 근거로 답하는 AI 챗봇을 붙인다. 독자는 내 상황에 맞는 답·출처 글·바로 해 볼 기능을 받고, 운영자는 반복 응대를 자동화하며 답하지 못한 질문을 다음 글 주제로 쓴다.

2. 문제

문제 정의(한 문장): 지친 독자는 답이 어느 글에 있는지 몰라 이탈하고, 1인 운영자는 같은 질문에 반복해서 답한다.

독자: 지친 20~30대는 긴 글을 읽을 여유가 없다. ① 답이 어느 글에 있는지 몰라 ② 이탈하고, 호흡·게임 같은 마음버블 기능으로 이어지지 않는다(블로그 → 서비스 유입 경로 없음).
운영자: 1인 운영이라 ④ 같은 질문에 반복해서 답하고, ⑤ 독자가 무엇을 궁금해하는지 데이터가 없어 글 주제를 감으로 정한다. ③ 위기 표현은 놓치면 안 된다.

데스크리서치 현황 시사점
블로그 검색(티스토리 등) 키워드 일치 검색이라 "잠이 안 와요" 같은 문장 질문에 약함 문장형 질문을 이해하는 검색 필요
범용 AI 챗봇 내 글·내 서비스를 모르고 출처가 없음 답의 근거를 내 글로 묶어야(RAG) 신뢰·유입이 생김
멘탈케어 앱 기능은 많지만 가입·설치 장벽 가입 없는 웹이라 "블로그 → 바로 체험"이 쉬움

타깃 사용자

  • 지친 독자(주): 20~30대 직장인·학생, 퇴근길·잠들기 전 모바일 접속.
  • 정신건강의학과 환자(주, 상용화 단계): 병원 치료 프로그램에서 의료진이 권하는 보조 도구로 진료 사이 자기관리를 돕는다. 선행 조건: 치료 대체 금지, 디지털의료제품법상 해당 여부 검토·인허가, 건강정보 별도 동의·암호화, 임상 근거. MVP는 진단·처방성 답변 금지, 개인 기록 미수집으로 설계한다.
  • 운영자(부): 응대 시간을 줄이고 글 주제를 데이터로 정하고 싶은 1인 기획자.

5. 출시·운영·마케팅과 리스크

  • 출시: push → Actions(테스트·빌드) → Firebase Hosting. Cloud Functions는 유료라 AI Logic(Gemini, 무료)을 브라우저에서 호출 + App Check(D-007).
  • 운영: 주 1회 Firestore content_gaps 질문으로 글 주제 선정. 새 글은 push만 하면 챗봇이 바로 근거로 씀.
  • 마케팅(마음버블 유입): 블로그에서 서비스로 가는 경로가 없던 문제를 글마다 "마음버블에서 해 보기" 버튼, 답변의 기능 링크로 연결하고, 위로카드 공유에 블로그 주소를 넣어 되돌아오게 한다. 지표는 기능 링크 클릭률(UTM utm_source=maeum-blog).
  • 기관 서비스로의 활용: 근거 문서로만 답하기·위기 규칙 우선·개인 기록 미수집은 병원·기관용 보조 도구의 필수 조건이다. 갭 로그·안전 테스트 방식을 기관 콘텐츠 검증 절차로 확장한다(D-008).
